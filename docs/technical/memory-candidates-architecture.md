# 候选审核、冲突处理与中文检索（Refs #18）

本项按 2026-10-09 的维护者授权开发并提交草稿。最终验收边界见 [验证记录](memory-candidates-validation.md)；代码或夹具测试通过不代表真实模型或人工验收通过。

## 自动候选的授权和调度

沿用应用配置 `memory.automaticCandidates`，默认 false。源会话的发布版本、应用当前发布版本和已保存草稿均须开启；保存关闭草稿立即撤销派发资格。没有全局记忆开关。启用只作用于随后成功的普通运行，不回溯旧会话，不提取试运行、工具输出、附件或助手消息。

每个成功运行的第一条完整用户消息是确定来源，记录 appId/conversationId/runId/messageId。模型输入是固定说明和 JSON 数据，最多 6000 UTF-8 字节（保守 token 上界，包含说明和 JSON 开销）；先检查整个来源的明显凭据，再按 Unicode 码点截断。使用来源版本的模型配置。配置 UI 告知发送范围及隐私边界。

`RunScheduler` 在原运行完成后独立事务创建提取任务。只有主队列及活动运行均为空时才占用一个独占全局槽；提取期间新主任务排队，因此不会越过全局、模型、本地并发限制。这是有意保守的首版：后台提取可能被持续的主任务延后，一次提取最多阻塞后续任务 30 秒。最多 100 个 outstanding 提取；超额任务以 QUEUE_FULL 独立失败。失败不会改写原成功运行。

提取通过既有 provider worker 的受限 SSE 传输，使用独立 Worker、64MB JS heap、最迟 30 秒终止、无工具/技能/会话文件/权限桥、无 SDK 自动重试，输出上限 1024 token / 8192 UTF-8 字节（传输流另有 64KiB 上限）。工具调用、无效终止、超限和非 schema JSON 都失败；只返回固定错误枚举，丢弃 SDK stdout/stderr 和错误正文。模型仍可能错误抽取或遵循恶意数据；工具禁用、严格 schema 和人工确认共同限制影响，并不宣称能完美阻断语义提示注入。

任务状态为 pending/running/succeeded/failed/cancelled，独立持久化版本和尝试计数。去重键是 appId、messageId、来源内容/创建时间哈希、策略 `user-message-v1` 的哈希。失败只能显式重试，最多 3 次模型调用；已成功（包括全部过滤/重复/拒绝）任务不能重试。启动把 running 标记为 failed/INTERRUPTED，不自动重试；pending 继续经过授权检查。异常的成功运行与任务入队之间若进程崩溃，可能漏提取；不会自动重放原运行。

模型返回前及事务提交候选前再次检查来源状态、来源哈希和配置。删除/回收来源、归档应用或关闭提取会丢弃在途结果；已发送到模型的输入无法撤回。已有候选保留供拒绝；关闭提取后仍可审核，删除来源后不能接受。用户已确认记忆不因删除来源自动失效，仍可显式停用/删除。

## 审核、去重和版本

候选存于不可变 `memories` 版本，状态 candidate/conflict；`memory_candidates` 保存任务、规范化内容及模型主题提示。明显凭据（包括全角形式）、临时日志/短期内容与部分明显命令文本被过滤；这不是完整 DLP。手动确认、修改后确认也复用凭据检查。

重复规则：同一应用、最新版本、未过期的 active/candidate/conflict 内容经 NFKC、小写和去标点/空白后完全相等。自动重复只跳过新候选，不改写有效事实。拒绝创建 deleted 版本，提取任务及其去重键保留，重试同源不会复活。不同来源可提出同样内容供重新审核。

疑似冲突只在同一类型中识别：内容冒号/等号前的规范化主题相同，或旧内容含有候选给出的至少两个字符的主题提示，或内容规范化相同。包含有效记忆以及其他候选；列表动态重算，因人工编辑而变化的目标会使旧审核失败。它不完整理解否定、时间、指代或同义词，可能误报/漏报；不把自动主题提示当事实。

未审核候选始终不检索/注入；发生疑似冲突时保留用户已确认旧事实。用户可接受无冲突候选、修改后接受、拒绝、保留对照条目、替代或合并。替代/合并会在同一 SQLite 事务中：创建候选的 active 新版本、停用每个对照条目的新版本、写入 `memory_supersedes`，保留准确的旧 ID/版本。并发审核、旧 candidate expectedVersion、已编辑/新增/删除的冲突目标或不完整 targets 集合返回 VERSION_CONFLICT，不部分写入。修改后的内容也再次检查疑似冲突。普通手动 update 不允许绕过 candidate/conflict 审核。

## 派生搜索索引 v1

迁移 10 增加可重建 `search_documents` 和 FTS5。规范化为 NFKC、小写、去除非 Unicode 字母/数字；原始内容及版本保留在消息/记忆中，用于展示与溯源。按 Unicode 码点生成 unigram + bigram，再编码成十六进制 ASCII token，因此不依赖默认英文分词的中文效果。跨标点的相邻字符也生成 bigram。

- 短语：FTS bigram AND 后核对规范化连续子串；单字用 unigram。
- 术语：将用户输入按非字母/数字分隔，每个术语生成 bigram 并 AND，允许中英术语之间顺序不同。
- 基础模糊：bigram OR 召回，匹配查询 gram 至少 50%。只提供字符近似，不提供拼音、同义词或语义搜索；短词错字召回较弱。

MATCH 只包含平台生成并引用的 hex token；appId、kind、时间、分页等均绑定。SQL 层限定 appId，计数/片段/结果没有全局共享返回或建议。按更新时间降序、ID 升序稳定分页，返回原文、定位片段及空结果。片段按规范化字符映射原文位置；UI 只渲染文本，不执行 HTML。

写入/编辑消息和写入新记忆版本时，SQLite 触发器在同一事务中更新索引；非 active 记忆立即移出，流式/工具消息不进入；会话回收移除消息索引。过期用查询时刻过滤，避免时间经过导致陈旧命中。重建从原数据的最新有效版本/完整活动会话消息创建，事务整体提交，失败回滚到旧索引；索引版本不符时拒绝搜索/注入，不回退全库搜索，也不使用半成品。原消息、记忆和历史引用不因重建而改变。

注入先经 scoped FTS 筛选，按预计算 grams 评分、优先级、更新时间、ID 最多召回 1000 条，再沿用中文关键词相关性及完整条目预算装配与审计。查询最多使用前 1000 UTF-16 代码单元；超长输入/大量近似内容可能降低召回，已有默认 8 条 / 1500 保守 token 预算保持不变。索引失败不会扩大查询范围。

已有直接内容读取、备份和历史引用保留语义不变；这不是向量数据库、云同步、全局共享记忆或自动事实判断系统。
