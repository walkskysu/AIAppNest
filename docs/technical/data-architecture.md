# 一致性备份、恢复与回收站

Refs #19。首版使用 `.aibackup` **目录包**，不是 ZIP。复制整个目录即可迁移。没有解压器、压缩比或脚本执行入口；不支持云备份、增量备份和跨账户密钥导出。

## 服务与一致性边界

Main 的系统文件夹选择器签发内存令牌，绑定页面代次、用途（backup/package/restore）和十分钟有效期。Renderer 不能传入路径。创建/恢复消费令牌；preflight 可重复读取同一个包令牌。IPC 返回作业 ID，`backups.status/cancel` 查询或取消，界面可查看持久化作业记录。

DataService 独占维护作业。Service Host 立即阻止新的业务写请求，RunScheduler 停止接收新运行和启动新记忆提取；已受理的队列、活动运行及当前提取先结束。等待时可取消运行、处理其权限请求、取消备份。然后关闭所有空闲 Worker、落盘事件并等待已进入的文件/凭据异步写入结束。冻结覆盖 SQLite 快照和全部文件复制，`finally` 恢复调度。不是运行中直接复制 `platform.db`；Storage 调用 Node `node:sqlite` 的 `backup()`，包括 WAL 已提交数据。

维护锁只在内存。启动把遗留 waiting/copying/verifying 作业标记 interrupted，不自动执行。未完成输出使用 `.incomplete-<job>` / `.restore-<job>`；正常异常清理暂存目录，崩溃残留保留这个明确前缀且不会作为成功输出展示。可在核对作业失败且服务关闭后手动删除该作业残留。发布只重命名到不存在的最终目录，不覆盖已有包。

## 包内容与校验

`manifest.json` 保存格式、schema、Node/Pi/adapter/extension/session 版本、时间、includesRecycle、排除项、相对路径/字节数/SHA-256、精确 sessionFile 映射。首个 v1 包为 schema 11；拒绝更早的非 v1 数据库、未来 schema、迁移历史校验和不符以及不同固定运行时，不下载安装或替换 Pi。

- 包含 `data/platform.db`、应用全部版本与快照、共享 Skill、原始 Pi JSONL、托管附件/产物/工作空间和未彻底删除的回收站数据。
- 排除 `credentials`（含机器绑定密文）、会话 `agent` 运行时目录、缓存、日志、历史备份及作业计划。快照中清空 secretRef、外部 grants、policy_records 和 data_jobs，VACUUM 去掉快照空闲页内的旧凭据引用。原数据库不受这些处理影响。
- 外部目录不会被遍历/复制，原授权全部作废。模型配置保留，但需要密钥的模型在重新绑定前不可运行。用户主动写进聊天/文件正文的秘密属于用户内容，不是凭据仓库的可识别密钥字段，备份不是正文脱敏工具。
- 逐文件大小与哈希校验，并核对 SQLite integrity/foreign keys、迁移历史、应用快照/资源、共享及版本内 Skill 哈希、附件/产物元数据和每个会话的精确 JSONL。不能从清单中删掉一个仍被数据库引用的文件来绕过校验。
- 拒绝绝对路径、`..`、反斜杠、空段、Windows 设备名/ADS/尾点空格、大小写重名、符号链接、junction、硬链接和额外文件。配额为十万文件、总计 20 GiB、单文件 512 MiB、清单 32 MiB；Pi 会话另遵循现有读取器的 32 MiB 上限。恢复复制逐块计数并校验，防止源包在预检后变大造成无界展开。

## 新目录恢复和切换

`backups.preflight` 校验整个包；`backups.restore` 在选择的父目录创建新的 `.restore-*`，不会覆盖当前目录。暂存 Storage 执行受支持迁移、重建派生搜索索引并校验数据库归属；遗留运行按 queued→cancelled、其余→interrupted 处理，待提取任务取消，不重放提示或副作用。

将 DB 的 sessionFile 映射到最终目录的**精确原文件名**，不使用 `--continue`。固定 session v3 的头部 cwd 映射到新根，其余 JSONL 字节保持原样；不改写消息、工具结果或会话逻辑。凭据引用再次清空，所有外部授权再次撤销。验证结束并写入 `restore-ready.json` 后才发布 `restored-*`，作业成为 ready。失败仍可重新选包和目标重试。

显式点击“停止服务、切换并重启”后 Main 停止服务，在 Electron profile 写入 fsync 后原子重命名的 `data-root.json`（active、previous）。重启只选择一个根：未提交指针的临时文件忽略；已提交且有完整 ready 标记的 active 优先；active 缺失/标记破损则选择存在的 previous 数据库。指针格式错误或两根均不可用时停止启动，不猜测、不合并。原目录和旧备份不删除。切换失败重新启动并按已提交指针选择，避免留下永久关闭的服务对象。

ready 标记表示暂存校验完成，不是长期防篡改签名；后续数据库损坏由既有启动错误处理报告。手工回退必须先完全退出应用，再备份 profile 指针并移走 `data-root.json` 以返回最初默认目录；若 previous 不是最初默认根，应将指针 active 改为那个仍带 ready 标记的 previous。不要复制旧数据库到新根或混合其附件。

## 删除范围和重试

归档仅停用；回收站软删除保留原文件与归属，且应用恢复不会恢复此前单独回收的会话。应用和会话须先取消活动任务、确认 Worker 退出再归档；若返回 BUSY，界面显示未完成，等待终止后再次操作。普通取消归档不能绕过回收站或删除墓碑。

彻底删除必须来自回收站并显式 confirm。预览列出会话、附件、记忆版本、产物和 Skill 引用数；聊天/附件必删，来源记忆和托管产物可分别保留。清理内容包括原始 sessions、agent/workspace、托管附件、所选产物、消息/运行事件/关联、候选/提取记录和索引。保留记忆/产物时保留不可运行的来源墓碑、必要运行/版本归属；外部目录只删除授权与平台引用。

删除计划先持久化。所选记忆在任何可能失败的文件操作前退出未来检索；文件完成后才事务删除元数据并同事务记录 metadataDone。共享 Skill 仅在没有其他应用版本、回收站或草稿引用时清理。文件失败作业为 failed，启动中断为 interrupted；`recycle.retry` 使用原选择继续，已删除文件可重复处理。metadataDone 后失败也能继续清理 Skill。失败作业未清理前禁止该应用恢复及备份，避免把半删除数据宣称为完整备份。

作业记录保存类型、状态、数量、时间、稳定错误码和本地结果路径；软删除/恢复与元数据清理有独立操作记录，不记录聊天/文件内容、密钥或底层异常文本。界面提供取消、校验结果、恢复影响说明、凭据设置入口和失败清理重试。备份保留由用户手动管理，不自动删除唯一备份。删除当前数据不会擦除历史备份，也不承诺物理介质安全擦除。
