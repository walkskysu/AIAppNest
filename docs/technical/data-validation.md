## 独立新目录与新账户演练步骤

1. 在专用测试 Electron profile 启动；创建明确授权的测试模型配置、应用和 Skill，产生至少一次含附件的实际运行与实际产物，保存一条有来源的记忆。记录 ID、原会话/附件/产物哈希和文件大小，不记录密钥或正文。
2. 启动另一个活动任务，点击“创建一致性备份”选择测试输出目录。核对正在等待且不能新增运行；试一次取消，再重试并完成活动任务。确认仅最终 `.aibackup` 作为成功结果，清单包含回收站、版本/哈希和排除项。
3. 将整个目录包复制到独立测试父目录（含中文和空格，优先不同盘）。选择包并校验，再“恢复到新目录”。核对 ready 前原根未被覆盖；ready 后记录新根与所有文件校验结果，再显式切换重启。
4. 在“模型设置”重绑凭据。外部读/写目录重新经过系统选择和确认。打开原会话继续指定测试问题，核对原上下文、sessionFile 精确文件名、新根前缀和无旧根文件写入；核对附件/产物真实字节、记忆检索和 Skill 内容。
5. **在人工创建的全新普通 Windows 账户重复步骤 3–4**。该账户只接收非秘密包和测试原文件，不复制 credentials 或旧授权。重新绑定前应拒绝需要密钥的运行；重新授权前不能访问原外部目录。记录新账户演练日期和脱敏账户标识、包哈希、运行 ID、文件哈希、权限拒绝及重绑后证据。
6. 在测试副本进行损坏包/迁移失败和切换中断演练，核对服务启动选择单个完整根及原根回退。不在共享宿主直接断电或耗尽系统盘。
7. 在测试数据中分别回收应用和会话，恢复并核对索引。彻底删除分别测试“保留记忆/产物”和全删；另一应用及其回收站引用相同 Skill，确认不被删除。人工占用一个托管文件导致清理失败，释放后重试，确认未完成状态不会假报成功。验证外部原文件和旧备份仍存在。

每项标注 AUTOMATED / INJECTED_FAULT / REAL_ENVIRONMENT / MANUAL，保存脱敏结果，不以行数、夹具成功或代码合并替代真实数据/新账户验收。失败需记录是否可重试、启动选择哪个根及旧根是否可用。
